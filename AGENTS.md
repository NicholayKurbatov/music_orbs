# Правила работы с Music Orbs

Инструкции действуют для всего репозитория. Явные указания пользователя
определяют текущую задачу и имеют приоритет над описанным здесь рабочим порядком.

## Текущий этап

Разрешены документация, структура каталогов, модели, интерфейсы и явные заглушки.
Реализацию renderer, DSP, захвата звука, UI и Android-сборки начинать только
по соответствующему указанию пользователя. Не выдавать заглушки за работающие функции.

Перед изменениями читать README.md и относящиеся к задаче документы:

- docs/scope.md — требования и границы продукта;
- docs/design.md — архитектура и владение состоянием;
- docs/spec.md — публичные контракты;
- docs/tests.md — критерии проверки;
- docs/references.md и docs/reuse.md — визуальные цели и переиспользование.

## Clean Architecture и DDD

- Сохранять контексты Sculpture, MusicalMotion, AudioSession и Experience.
- domain не импортирует application, infrastructure, presentation, Android, Three.js, DOM или IO.
- application зависит от домена и своих портов, но не от реализаций адаптеров.
- infrastructure реализует порты; presentation преобразует пользовательские события в сценарии.
- Создание зависимостей и выбор адаптеров выполнять в bootstrap.
- Не превращать каждый контекст в отдельный сервис без обоснованной необходимости.
- Общий PcmFrame — ограниченный published language между AudioSession и MusicalMotion.
- Kotlin/JavaScript взаимодействуют через versioned DTO с явным enum/Vec3 mapping.

## Инварианты продукта

- Разделять базовую геометрию, постоянную деформацию и временную анимацию.
- Деформацию хранить в object space и независимо от индексов частиц/качества.
- Сохранять непрерывность фазы при смене BPM, источника и режима синхронизации.
- Отбрасывать старые sourceSessionId и bridgeSessionId, не копить неограниченные очереди.
- Источник аудио не должен влиять на API renderer и не должен сбрасывать форму.
- Не включать микрофон автоматически вместо неработающего внешнего захвата.
- Не обещать поддержку конкретного плеера без проверки устройства и разрешений.
- Не отправлять PCM в сеть и не сохранять аудиозапись в рамках текущего scope.

## Переиспользование

Сначала проверять docs/reuse.md и подходящие upstream-модули.
Переиспользовать библиотеку или изолированный фрагмент, когда он подходит контракту;
закрывать внешний API адаптером. Не переносить целиком demo UI и recording-приложения.
При включении стороннего кода записывать URL, commit, исходный/целевой путь,
изменения, copyright и лицензию в third_party. Не добавлять зависимость с
непроверенными условиями распространения. Пока код upstream не включён,
не утверждать, что модуль уже переиспользован в реализации.

## Документация и проверки

- Требованиям давать стабильные FR/NFR ID и связывать их со сценариями приёмки.
- Изменение публичного метода сопровождать обновлением spec.md: входы, атрибуты,
  единицы, результат, инварианты, ошибки, эффекты и границы ответственности.
- При изменении файлов обновлять docs/tree.md и локальные Markdown-ссылки.
- Отделять обязательные требования, проектные предложения, открытые вопросы и измеренные результаты.
- Не помещать в проект ID разговоров, пути к личным журналам или переписку о доступах.
- Документацию писать по-русски; программные идентификаторы — по-английски.
- Проверять локальные ссылки, покрытие требований сценариями и направления импортов.
- TypeScript-каркас проверять командой из README.md. Не утверждать успешную Android-сборку,
  пока сборочный проект не создан и соответствующая команда не прошла.
- Исполняемые функциональные тесты добавлять вместе с реализацией;
  планы тестирования и статические проверки не считать прохождением сценариев приложения.

## Рабочий процесс

Проверять git status и сохранять существующие пользовательские изменения.
Стейджить только файлы задачи; перед коммитом просматривать staged diff и diff --check.
Коммит создавать по запросу пользователя; публикацию выполнять при наличии указания.
При длительной работе не реже раза в 10 минут сообщать, что сделано, что осталось
и ориентировочный процент текущей задачи. Не интерпретировать этот файл как
самостоятельное разрешение запускать несколько агентов: делегирование — по отдельному указанию.
